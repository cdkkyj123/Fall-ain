# ADR-002: 친밀도(intimacy) 최종 확정은 서버 결정론 점수표

## Status
Accepted

## Context
"경청이 사랑"의 핵심 훅은 감정 주체 이전이다 — AI가 대화 중 흘리는 사실(Canon)을 유저가 능동적으로 기억하고 되짚어야 호감(intimacy)이 상승한다. 이 되짚기의 정확도와 타이밍을 평가해야 friendly/intimacy 점수를 산정할 수 있다.

이 평가에는 자연어 이해가 필요하므로 LLM의 관여가 불가피하다. 그러나 LLM 출력을 그대로 점수로 사용하면 다음 문제가 발생한다.

- LLM은 동일 입력에도 확률적으로 다른 출력을 낼 수 있어 재현성이 없음
- 점수 인플레이션/편향 등 LLM 특유의 불안정성이 게임 밸런스를 해침
- 점수 산정 로직이 프롬프트 안에 암묵적으로 존재하게 되어 감사(audit)·튜닝이 어려움

## Decision
역할을 분리한다.

- **LLM의 역할**: 유저의 되짚기 발화가 실제 Canon 사실과 얼마나 일치하는지, 그리고 대화 맥락상 타이밍이 적절한지에 대해 판정 신호만 출력한다.
  - 정확도 신호: `EXACT` (정확히 일치) / `PARTIAL` (부분적으로 일치) / `WRONG` (불일치)
  - 타이밍 신호: `FITTING` (맥락에 자연스럽게 부합) / `FORCED` (억지로 끼워 맞춤)
- **서버의 역할**: 위 판정 신호 조합을 입력으로 받아, 서버에 고정된 상수표(예: `EXACT+FITTING` → +N점, `PARTIAL+FORCED` → +M점 등)를 통해 최종 intimacy 점수 변화량을 결정론적으로 계산한다. LLM은 점수 숫자를 직접 산출하지 않는다.

## Consequences

### 긍정적 영향
- 동일한 판정 신호 조합에 대해 항상 동일한 점수가 산출되어 재현성/일관성 확보
- 점수 밸런스 조정 시 프롬프트를 건드리지 않고 서버 상수표만 수정하면 됨
- LLM 응답 파싱 실패나 이상값에 대한 방어(fallback)가 서버 로직에서 명확하게 처리 가능
- 점수 산정 로직에 대한 테스트 작성이 용이해짐 (LLM 호출 없이 상수표 단위 테스트 가능)

### 부정적 영향 / 트레이드오프
- 판정 신호의 세분화 수준(EXACT/PARTIAL/WRONG, FITTING/FORCED)이 거칠어 미묘한 뉘앙스 차이를 반영하지 못할 수 있음
- LLM의 판정 자체가 부정확하면(예: PARTIAL을 EXACT로 오판) 서버 상수표가 아무리 정교해도 결과 품질에 한계가 있음
- 상수표 설계·튜닝에 별도 밸런싱 작업이 필요함

### 재검토 조건
- 판정 신호의 표현력이 부족하다고 판단되는 경우 신호 카테고리 확장 검토
